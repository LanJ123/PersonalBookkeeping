## 2. 用户确认结果

用户于 2026-07-21 回复“按原型确认”，形成 v1.0 基线；2026-07-26 形成 CR-004/005；2026-07-27 进一步要求首页按天聚合、统计全局收支联动和图表数据标签，形成 CR-006。以下 v1.3 设计取代受影响的 v1.2 条目：

1. 首页当前月流水按本地发生日期分组；日期组头显示星期、当日支出和收入小计，组内保持时间倒序。
2. 统计页的支出/收入为全局筛选，统一控制 2×2 汇总、单条趋势线、分类构成/排行、分类下钻和周期柱图。
3. 汇总按参考图固定为周期总额、日均、比上一周期、收支结余；收入模式使用对应收入指标。
4. 趋势图补人民币纵轴，环图直接标分类百分比，柱图逐柱显示金额；文本排行继续保留分类笔数、金额和占比。

## 3. 已知设计风险

- 记账分类数量多时，分类选择需在高保真原型中验证“最近使用 + 全部分类”的密度。
- 小屏设备和大字体下，首页两项月度辅助汇总、年月操作行和分类排行允许换行或调整间距，不能截断金额与年月。
- 月统计最多 31 个趋势点，界面只显示首、中、末横轴标签；完整逐点数据由无障碍语义提供。
- 分类很多时引导线标签可能密集；实现需做左右分栏与纵向避让，完整排行继续作为精确数据兜底。
- 五个柱顶金额在窄屏可能拥挤；允许紧凑字号，但不得隐藏金额，完整值同时保留在可访问语义中。
- 系统文件选择器由设备 ROM 提供，备份/恢复说明必须避免暗示应用控制了外部云盘。
- 主力机型号尚未登记，手势导航、系统认证和深色模式需在技术设计前补录测试环境。

## 5. CR-006 核对要求

- 首页证据需同时包含至少两个日期组、每组当日支出/收入小计及组内流水。
- 统计证据需分别包含支出与收入模式，清楚显示 2×2 汇总、单条趋势线和金额纵轴。
- 向下滚动证据需包含环图分类百分比、排行笔数/金额/占比及五周期柱顶金额。

## 6. 阶段门结论

CR-006 不改变四主导航、离线事实源、备份格式或数据库 schema；它细化首页分组表达，并把统计的收支筛选提升为全局状态。设计、实现和测试以 v1.3 条目为准。
