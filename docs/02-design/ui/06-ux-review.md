| 检查项 | 结论 | 说明 |

| 高频记账路径 | 通过 | 全局入口直达编辑器；金额、分类、账户、日期时间均可直接操作 |
| 导航一致性 | 通过 | 4 个一级入口；首页和流水使用一致日期卡片；首页固定今天/本月，流水负责历史年月；统计全局类型筛选与下钻使用同周期、同类型事实源 |

## 2. 用户确认结果

用户于 2026-07-21 回复“按原型确认”，形成 v1.0 基线；2026-07-26 形成 CR-004/005；2026-07-27 进一步要求首页按天聚合、统计全局收支联动和图表数据标签，形成 CR-006。以下 v1.3 设计取代受影响的 v1.2 条目：

1. 首页当前月流水按本地发生日期分组；日期组头显示星期、当日支出和收入小计，组内保持时间倒序。
2. 统计页的支出/收入为全局筛选，统一控制 2×2 汇总、单条趋势线、分类构成/排行、分类下钻和周期柱图。
3. 汇总按参考图固定为周期总额、日均、比上一周期、收支结余；收入模式使用对应收入指标。
4. 趋势图补人民币纵轴，环图直接标分类百分比，柱图逐柱显示金额；文本排行继续保留分类笔数、金额和占比。

## 3. 已知设计风险

- 记账分类数量多时，分类选择需在高保真原型中验证“最近使用 + 全部分类”的密度。
- 小屏设备和大字体下，首页两项月度辅助汇总、年月操作行和分类排行允许换行或调整间距，不能截断金额与年月。
- 月统计最多 31 个趋势点，界面最多显示八个均匀横轴标签；完整逐点数据由无障碍语义提供。
- 分类很多时引导线标签可能密集；实现需做左右分栏与纵向避让，完整排行继续作为精确数据兜底。
- 五个柱顶金额在窄屏可能拥挤；允许紧凑字号，但不得隐藏金额，完整值同时保留在可访问语义中。
- 系统文件选择器由设备 ROM 提供，备份/恢复说明必须避免暗示应用控制了外部云盘。
- 主力机型号尚未登记，手势导航、系统认证和深色模式需在技术设计前补录测试环境。

## 6. 阶段门结论

CR-006 不改变四主导航、离线事实源、备份格式或数据库 schema；它细化首页分组表达，并把统计的收支筛选提升为全局状态。设计、实现和测试以 v1.3 条目为准。

## 7. CR-007 流水日期卡片

- 流水页保留年月、搜索、类型和组合筛选，仅将结果区统一为与首页一致的日期卡片。
- 日期、星期、当日支出/收入小计和组内流水位于同一视觉容器；各笔之间使用分割线，不再一笔一张卡片。
- 每笔补充发生时间，保留分类、账户/转账流向、备注、正负金额和详情入口。
- 数据查询、Paging、筛选条件、每日汇总口径、数据库 schema 和备份格式均不变。

## 8. CR-008 全应用 iOS 风格视觉评审

- 全局颜色、排版、圆角和表面层级已收敛为一套浅色/深色 token，业务页不再各自定义视觉方向。
- 首页重点金额使用浅蓝摘要卡；流水和分类排行继续采用分组卡片，确保高密度信息仍可快速扫描。
- 底部导航改为四个线性入口图标与居中蓝色新增按钮，文字标签和测试语义保留。
- 统计、记账与主题选择采用同一分段控件，选中态不只依赖颜色。
- 设置首页改为两组列表，入口名称、说明、彩色标识和层级箭头完整。
- 首页、流水、统计和设置采用一致的大标题起始位置；根页面不再叠加内层状态栏安全区。
- 本次仅调整表现层，不改变导航目的地、数据口径、筛选行为、保存流程或高风险确认。

## 12. CR-013 统计图动态纵轴复核

- 真机参考应用采用随实际峰值变化的人民币纵轴、稀疏竖向日期网格、折线下渐变面积、选中点光晕和金额气泡；本应用采用同类信息表达，不复制其品牌资源。
- 支出数据峰值 ¥734.30 时生成 ¥150、¥300、¥450、¥600、¥750、¥900 六档；收入峰值 ¥2,500.00 时独立生成 ¥500～¥3,000 六档，证明支出/收入筛选未共享固定上限。
- 最后一个零值点贴合基线；点击实际峰值后气泡更新为对应日期与金额，靠近右侧边界时未溢出卡片。
- 月横轴显示 1、5、9、13、17、21、25、29 日八个标签，竖向网格与标签对齐；完整 31 点仍保留无障碍文本。
- 周期柱状图按当前五周期峰值缩放，所有柱顶金额可见且最高金额与卡片顶部之间保留安全间距。
- 分类环图原有百分比引导线和排行中的分类笔数、占比、金额保持不变。
