# UX 设计规格

> 版本：v1.0（设计基线）  
> 日期：2026-07-21  
> 输入基线：需求 v1.0
> 确认状态：用户已于 2026-07-21 按原型确认

## 1. 设计目标

1. 首页到保存普通支出不超过一次页面切换；金额、分类、账户在首屏完成。
2. 高频查看以“本月概览 + 最近流水”为首页，不把复杂资产信息堆在首屏。
3. 所有统计都能回到组成它的流水，避免图表成为数据孤岛。
4. 数据恢复、删除等高风险操作强调对象、影响与可回滚性。
5. 极简不是隐藏关键状态：筛选、预算超支、停用账户和恢复结果必须清楚可见。

## 2. 导航模型

底部 4 个一级入口：`首页`、`流水`、`统计`、`设置`。居中的“记一笔”作为全局主操作，但不新增第五个信息层级。

- 首页：本月收入、支出、结余、预算进度、最近流水。
- 流水：完整事实列表，负责搜索、筛选、详情、编辑和删除。
- 统计：月份切换、分类排行/占比、收支趋势和下钻。
- 设置：预算、账户、分类、备份恢复、CSV 导出、外观和应用锁。

返回规则：编辑器取消后返回发起页面；保存后返回发起页面并显示成功反馈。统计下钻进入带固定筛选条件的流水页，返回时保留统计月份。

## 3. 记账编辑器

顶部使用 `支出 / 收入 / 转账` 分段选择，默认支出。字段顺序依据使用频率：

1. 金额：自动聚焦，人民币符号固定展示；不预填 0。
2. 分类：显示最近使用与全部分类；收入/支出切换时更换集合。
3. 账户：默认最近一次同类型交易使用的活动账户。
4. 日期与备注：默认折叠为“更多”，修改后在摘要行展示。
5. 保存：始终有可见文字，不使用只有图标的确认按钮。

转账模式将“分类”替换为“转出账户 / 转入账户”，当两者相同时立即就地报错。键盘上的完成操作不等于保存，避免误提交。

## 4. 首页层级

- 第一层：月份切换和隐私金额遮罩。
- 第二层：支出为主数值，收入和结余为辅助数值。
- 第三层：预算进度，只有设置预算后展示；超支不阻止记账。
- 第四层：最近 5 笔流水和“查看全部”。

空账本首页不展示一排 0，而展示“记下第一笔”主操作，并保留备份与隐私说明入口。

## 5. 流水与筛选

- 默认按发生时间倒序、按天分组；组头显示日期与当日收支小计。
- 顶部搜索匹配备注；筛选按钮显示生效数量，例如“筛选 2”。
- 筛选面板包含日期、类型、账户、分类；应用后在列表顶部显示可移除条件。
- 详情页先显示交易事实，再放编辑和删除操作。删除位于低强调区域且二次确认。

## 6. 统计与预算

- 统计默认当前自然月，月份控件与首页一致。
- 首屏顺序：收入/支出/结余 → 分类支出排行 → 每日趋势。
- 分类用排行条和数值表达，占比图仅作辅助；点击整行下钻。
- 预算同时显示“已用 / 总额 / 剩余”，80% 使用“接近预算”文字，100% 使用“已超支”文字，不能只靠颜色。

## 7. 视觉方向

采用克制、轻量、数据优先的视觉：单一高强调操作色；收支方向除颜色外始终带 `支出/收入/转账` 文本或正负号；卡片只用于真正的汇总或输入边界，不为每一行制造容器。

具体颜色、字体、间距 token 在视觉设计/技术设计交界阶段结合 Material 3 固化，本阶段不锁死品牌色。

## 8. 原型范围

交互原型覆盖首页、流水、统计、设置、三类记账切换和保存反馈，用于验证信息层级与主路径。它是低保真行为样例，不代表最终字体、图标、颜色和精确尺寸。
