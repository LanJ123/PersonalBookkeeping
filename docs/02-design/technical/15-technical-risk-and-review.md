## 1. 技术设计自检

| 检查项 | 结论 | 说明 |
|---|---|---|
| 稳定依赖策略 | 通过 | 固定 AGP/Kotlin/Compose BOM/Room/Navigation 稳定版本，不用预览依赖 |
| 离线与权限 | 通过 | 无网络、无广泛存储权限，SAF 显式选择文件 |
| 金额一致性 | 通过 | Long 分、单一事实流水、事务与双层校验 |

| 机器可读产物 | 通过 | 两份 JSON Schema 可解析；参考 DDL 已在内存 SQLite 执行，非法转账触发器与余额派生行为通过 |

## 2. 主要风险

| 风险 | 概率/影响 | 缓解与接受标准 |
|---|---|---|
| API 37 AVD 本机内存不足 | 高/低 | API 37 改为可选、非发布门槛；保留镜像/AVD，资源允许或有其他测试环境时补做；API 28/36 与真机仍强制 |
| 用户主力机型号未知 | 中/中 | 首次设备测试前登记；低于 API 28 则重新评审平台基线 |
| 未加密外部备份泄露 | 中/高 | 创建前明确提醒；用户显式选位置；P1 评估口令加密 |
| Room 触发器不在 Entity 声明内 | 中/高 | 创建/迁移显式重建；设备测试查询 `sqlite_master` 并验证行为 |
| 厂商对系统自动备份语义不同 | 中/高 | allowBackup=false + 两代全排除规则 + 目标机实际备份审计 |
| 1 万笔时备注 LIKE 搜索偏慢 | 中/中 | 先基准；仅达不到 1s 时用 FTS5 ADR 变更 |
| API 37 仍处预览/变化 | 中/低 | target 36；API 37 只做可选兼容性检查，不引入专有 API |
| 恢复中进程死亡 | 低/高 | SQLite 事务、pre-restore 快照、恢复日志、启动时恢复审计 |
| Compose/Navigation 升级回归 | 中/中 | BOM、稳定版、版本固定、升级单独 PR 与 UI 回归 |

## 3. 实现阶段补录

- 用户主力手机型号、Android 版本、可用文档提供者。
- 签名密钥保管位置（不得提交仓库）。

这些是环境/交付细化，不改变当前架构。若主力机低于 API 28、必须加密备份或需要自动任务，则属于正式范围/技术变更。
