# CR-008 iOS 风格 API 36 视觉验证报告

> 版本：v1.0
> 执行日期：2026-07-29
> 被测版本：本地 `debug` 构建
> 设备：PBK_API_36 模拟器，Android 16 / API 36，1080 × 2400

## 1. 结论

全应用 iOS 启发式视觉改造已完成 API 36 主路径核对：

- 首页、流水、统计与设置采用一致的内容区大标题，标题紧邻系统状态栏下方，不再叠加重复安全区；
- 根页面使用分组灰背景、白色内容卡、系统蓝强调色和一致圆角；
- 底部导航统一为四个主入口与居中蓝色新增按钮；
- 统计、记账和主题选择统一使用分段控件；
- 记账等二级页面采用紧凑返回栏，与根页面的大标题层级区分明确；
- 流水日期卡片、统计图表数据标签、日期时间选择和原有业务口径保持不变。

本次视觉核对未发现阻断问题。

## 2. 顶栏专项核对

首页、流水、统计与设置均由最外层导航统一处理系统状态栏安全区，页面内部不再创建第二层状态栏 inset。四个根页面的大标题使用相同字号、左右边距与顶部间距。

记账、预算、详情和管理类页面属于二级页面，继续使用带返回按钮的紧凑顶栏；其内部窗口 inset 设为零，由应用外层统一处理。

## 4. 构建与自动化结果

- `compileDebugKotlin`：通过；
- `testDebugUnitTest assembleDebugAndroidTest`：通过；
- `testDebugUnitTest assembleDebug installDebug`：通过；
- API 36 App instrumentation 全量运行：31/32 通过；
- 唯一失败为物理交互用例在全量执行末尾未发现保存按钮；同一用例隔离复跑通过，判定为测试顺序/设备状态波动，不是可复现产品缺陷；
- 流水日期卡片测试曾因页面头部增高后目标不在首屏而失败，已改为在 `LazyColumn` 内滚动查找；同时修正 Paging 刷新期间已有缓存流水被加载态遮挡的问题，定向复跑通过。

benchmark 与 App instrumentation 不再并行占用同一模拟器；此前并行运行产生的 benchmark 超时不计入本次 UI 验收。
