# 假设、风险与确认记录

## 1. 已确认约束

以下约束已于 2026-07-21 由用户按推荐方案确认，并纳入需求基线 v1.0：

1. 仅本人单用户使用，不登录、不联网、不跨设备实时同步。
2. 仅人民币，月份从每月 1 日开始；简体中文界面。
3. 目标手机为 Android 9 或更高版本，主要使用竖屏。
4. MVP 包含账户、手工收支/转账、流水、统计、预算、完整备份恢复、CSV 导出和可选应用锁。
5. 用户接受主动把备份文件保存到自己选择的位置；应用不负责云盘可用性。

## 3. 主要风险

| 风险 | 概率/影响 | 缓解措施 |
|---|---|---|
| 设备丢失/卸载导致本地数据丢失 | 中/高 | 首次产生数据后温和提示备份；备份校验；恢复演练 |
| 金额或转账计算错误 | 低/高 | 整数分、数据库事务、性质测试、从流水重算 |
| 备份格式随版本失效 | 中/高 | manifest 版本、迁移测试、保留兼容样本 |
| 范围膨胀拖慢首个可用版本 | 高/中 | 固定 MVP，新增需求进入 P1/P2 并记录决策 |
| 统计周期边界/时区造成差异 | 中/中 | 技术设计固化时区与月起始规则，覆盖边界测试 |
| 自动记账权限敏感且兼容性差 | 高/高 | 不进入 MVP；如后续开发需单独风险评审 |
| 目标设备厂商 ROM 行为不同 | 中/中 | 主力机实测 + 至少一台标准 Android 环境测试 |

## 4. 后续变更方式

需求已经基线化。任何范围变化应新增变更记录，说明提出日期、原因、受影响的 FR/DR/NFR、设计和测试影响，再决定纳入 MVP 或后续版本。目标主力机型号属于测试环境补充，不视为范围变更；若其 Android 版本低于 API 28，则需重新评审兼容基线。
