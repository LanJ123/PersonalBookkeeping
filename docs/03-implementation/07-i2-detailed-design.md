# I2 详细设计：账户、分类与流水

> 版本：v1.0  
> 日期：2026-07-22  
> 输入：需求 v1.0、UX v1.0、技术设计 v1.0、I1 已通过代码基线

## 1. 范围与退出条件

I2 覆盖 US-004、US-005，落实 FR-020～024、FR-030～033：

- 账户：新增、编辑、排序、停用；余额由期初余额和流水派生。
- 分类：按收入/支出新增、重命名、排序、停用。
- 流水：分页、按日分组、备注搜索，以及类型、日期、账户、分类组合筛选。
- 流水详情：事实展示、编辑、二次确认删除和短时撤销。

退出时必须通过 I1 全量回归、新增 JVM/Room/Compose 测试、API 28/36 设备矩阵、Debug/Release、Lint 和隐私审计。

## 2. 导航与界面

使用 Navigation 3 的可序列化 `NavKey`：

- 一级：`LedgerKey`、`SettingsKey`；首页/统计保留占位入口以维持四主导航结构。
- 编辑：`TransactionEditorKey(transactionId?)`，null 为新增，非 null 为编辑。
- 详情：`TransactionDetailKey(transactionId)`。
- 管理：`AccountsKey`、`CategoriesKey`。

根页面提供四个底部入口与全局“记一笔”。前进操作压栈，返回弹栈；底部入口切换清空非根目的地，避免把管理/编辑页留在错误栈中。

## 3. 流水查询契约

`TransactionFilter` 包含：

- `noteQuery`：规范化、转义 `%`、`_` 和转义符后通过参数绑定传入 `LIKE`。
- `type`、`accountId`、`categoryId`：可空，空表示不限；账户同时匹配来源与转入端。
- `fromEpochDay`、`toEpochDay`：可空且闭区间；领域层拒绝开始日期晚于结束日期。

Room DAO 返回 `PagingSource<Int, LedgerTransactionRow>`。SQL 中的日聚合子查询使用同一组筛选条件，避免跨页计算导致日期头小计不完整；UI 用 `insertSeparators` 插入日期头。

## 4. 编辑、删除与撤销

- 编辑读取完整领域记录；保存时保留 ID、创建时间和未编辑的发生时间，更新 `updatedAt`。
- 交易类型切换时重新应用 category/target 形状规则；数据库触发器继续作为第二层保护。
- 删除在 Room 事务中读取完整快照后删除。UI 只有二次确认后调用。
- 删除成功后返回流水并显示 Snackbar；用户点击撤销时以原 ID 和原时间字段重新插入快照。
- 撤销窗口随 UI 消失或应用终止而结束，不新增软删除字段。

## 5. 账户与分类规则

- 名称使用 Unicode NFKC、去全部空白、`lowercase(Locale.ROOT)` 生成活动名称键。
- 活动账户名不可重复；活动分类在同一 kind 内不可重复。领域层先检查，唯一索引最终兜底。
- 停用将 `status` 设为 `INACTIVE`、`active_name_key` 设为 null；历史名称和引用保留。
- 不提供物理删除。至少保留一个活动账户、一个活动支出分类和一个活动收入分类。
- 排序只交换相邻项目的 `sort_order`，在数据库事务中完成。
- 账户期初余额允许负数并使用 `Long` 分；编辑后派生余额即时重算。

## 6. 数据库与版本

I2 不新增表、字段、索引或视图，Room schema version 保持 1。只新增 DAO 查询和更新方法；导出 schema identity hash 必须保持不变。若实现中发现必须改表，则停止并按正式迁移流程处理，不在 I2 隐式变更。

## 7. 测试重点

- 名称规范化、重名、最后一个活动项、排序边界。
- 关键词特殊字符、组合筛选、日期闭区间、转账账户双端匹配。
- 编辑类型后余额旧影响被替换且只应用一次。
- 删除/撤销往返后实体与余额完全一致。
- 停用项不进入新增选项但历史详情仍可显示。
- 1 万笔性能留在 I5；I2 证明使用 PagingSource 且查询索引路径不被破坏。
