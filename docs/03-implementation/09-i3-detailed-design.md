# I3 详细设计：首页、统计与预算

> 版本：v1.0
> 日期：2026-07-22
> 输入：需求 v1.0、UX v1.0、技术设计 v1.0、I2 已通过代码基线

## 1. 范围与退出条件

I3 覆盖 US-006、US-007，落实 FR-040～045：

- 首页：所选自然月的收入、支出、结余、总预算进度和最近五笔流水。
- 统计：月度收支、支出分类排行与占比、逐日收支趋势。
- 下钻：从分类排行进入使用同一月份、支出类型和分类的流水筛选结果。
- 预算：按自然月设置总支出预算和可选分类预算；显示 80% 与 100% 状态提示。

退出时必须证明同周期统计可对账、预算边界正确、收入和转账不计入预算；通过 I1/I2 回归、新增 JVM/Room/Compose 测试、API 28/36 设备矩阵、Debug/Release、Lint、隐私和 schema 审计。

## 2. 月份与状态所有权

使用 `YearMonth` 表示用户所选自然月：

- `periodKey` 固定为 `YYYY-MM`。
- 查询起点为当月 1 日的 epoch day（含），终点为下月 1 日（不含）。
- 首页、统计和预算共享 Activity 级 `InsightsViewModel` 的所选月份；切换一级入口不重置月份。
- 前一月、后一月操作同时更新汇总、排行、趋势和预算，不允许不同模块持有隐式周期。

统计下钻把当前月转换为流水的闭区间，并固定 `type=EXPENSE`、`categoryId=<所选分类>`。返回统计页后月份仍由共享状态保留。

## 3. 聚合查询契约

I3 只增加 DAO 查询，不新增表、字段、索引或视图：

- 月汇总：仅 `INCOME` 计收入、仅 `EXPENSE` 计支出；转账不进入两者。
- 分类排行：仅统计支出，按分类分组，金额降序；分类合计必须等于月支出。
- 日趋势：仅返回存在收支事实的日期，按日期升序；UI 可补足视觉空白，但不得伪造金额。
- 最近流水：限制在当前月，按日期、发生时间和创建时间倒序取五笔。
- 预算：按 `ledger_id + period_key` 读取；总预算使用 `scope_key=TOTAL`，分类预算使用 `scope_key=CATEGORY:<categoryId>`。

所有金额继续使用 `Long` 分作为权威值。占比、进度条和图形坐标仅为展示派生值，不参与持久化或业务判断。

## 4. 预算规则

- 金额必须为正且通过既有 `Money.parsePositive` 约束。
- 保存同一作用域时更新原记录，首次保存创建稳定 ID；清除预算物理删除该预算记录。
- 总预算消耗等于当月全部支出；分类预算消耗等于当月该分类支出。
- 分类预算相互独立，其总和允许大于总预算；未设置总预算时不显示总预算告警。
- `used < 80%`：正常；`80% <= used < 100%`：显示“接近预算”；`used >= 100%`：显示“已超支”。提示不阻断继续记账。
- 阈值比较使用整数安全算法，避免浮点边界误判；剩余金额允许为负，仅作为派生展示。

## 5. 界面与可访问性

- 首页以本月支出为主要信息，收入和结余为辅助信息；无流水时显示“记下第一笔”。
- 已设置总预算时显示已用、总额、剩余和明确的文字状态；未设置时提供设置入口但不显示警告。
- 统计页面按“月汇总 → 分类排行 → 日趋势”排列。排行整行可点击，金额与百分比始终用文本表达；进度条和趋势图只作辅助。
- 趋势使用 Compose 原生 Canvas，不增加第三方图表依赖；同时提供日期、收入和支出的可访问性描述。
- 预算页支持编辑/清除总预算和活动支出分类预算，输入错误保持在当前对话框并显示原因。
- 所有关键点击目标按现有 Material 组件保持至少 48dp。

## 6. 分层与错误处理

- `InsightsRepository` 组合 Room 的月汇总、分类、日趋势、最近流水和预算 Flow。
- 预算状态由纯领域函数计算，便于 JVM 边界测试。
- `InsightsViewModel` 管理月份、加载状态、预算编辑结果和消息；UI 不直接访问 DAO。
- 初始化继续复用 `TransactionRepository.initialize()`；失败时显示本地错误文案，不崩溃、不发起网络请求。
- 预算唯一索引和既有触发器作为最终一致性保护；Repository 将数据库约束错误映射为可操作的中文提示。

## 7. 数据库与版本

`BudgetEntity`、唯一索引和触发器已属于 schema v1。I3 只新增 DAO、Repository 和查询投影，Room schema version 与导出 schema identity hash 必须保持不变。若构建生成结构差异，停止发布并进入正式迁移评审。

## 8. 验证重点

- 闰年、跨年和月末边界；切月后所有模块使用同一周期。
- 月支出等于分类支出之和，日趋势汇总等于月汇总。
- 收入和转账不进入预算；总预算与分类预算互不污染。
- 79.99%、80%、99.99%、100% 和超额边界。
- 分类排行下钻筛选契约与返回后的月份保留。
- 空月份、未设置预算、停用但有历史流水的分类。
- API 28/36、Debug/Release、Lint、无网络权限、禁用系统备份和 schema v1 不变。
