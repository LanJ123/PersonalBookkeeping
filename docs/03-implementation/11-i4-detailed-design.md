# I4 详细设计：数据可携带性与隐私

> 版本：v1.0
> 日期：2026-07-23
> 输入：需求 v1.0、UX v1.0、技术设计 v1.0、I3 已通过代码基线

## 1. 范围与退出条件

I4 覆盖 US-008～010，落实 FR-050～055：

- 通过 Storage Access Framework 创建 `.pbk` 完整备份和选择备份恢复，不申请存储权限；
- 在恢复前完成格式、版本、摘要、计数、引用和资源上限校验，显示复核摘要并由用户确认；
- 恢复采用“内部回滚快照 + 单个 Room 事务全量替换”，失败时原数据不变；
- 按日期范围导出 UTF-8 CSV，处理中文、逗号、引号和换行；
- 提供全局金额隐私开关和可选系统应用锁，不保存或自建 PIN/生物特征；
- 保持无 `INTERNET` 权限、关闭系统自动备份、Room schema v1 不变。

退出必须通过 JVM、Room、Compose、API 28/36 设备矩阵、Debug/Release、Lint、依赖校验、隐私和 schema 审计。API 37 继续按 DEC-018 为可选项。

## 2. `.pbk` 归档格式

归档固定使用 ZIP/Deflate，且只允许两个根目录文件：

1. `manifest.json`：格式版本、应用版本、数据库版本、创建时间、实体计数及 `data.json` 的字节数和 SHA-256；
2. `data.json`：账本、账户、分类、流水、预算和可携带偏好。

两个 JSON 均为 UTF-8、无 BOM、字段名固定为英文，解码时拒绝未知字段。`formatVersion=1`、`schemaVersion=1`、币种 `CNY`、自然月起始日 1。时间使用带偏移量的 ISO-8601，金额仍为 `Long` 分。

读取器逐个检查 ZIP 条目，拒绝重复条目、目录、绝对路径、`..`、额外文件和缺失文件。压缩输入和解压总量各以 100 MiB 为上限；账本固定 1 个，账户/分类各最多 10,000，流水最多 1,000,000，预算最多 100,000，备注最长 500 字符。数据摘要、清单计数、ID 唯一性、外键引用、流水形状和预算作用域全部通过后才生成恢复复核信息。

账户类型以已签署 Schema 为准：`CASH`、`BANK`、`E_WALLET`、`STORED_VALUE`、`CREDIT_CARD`、`OTHER`。旧开发库中的 `CREDIT` 只读映射为 `CREDIT_CARD`，`INVESTMENT` 只读映射为 `OTHER`；新写入一律使用规范值。

## 3. 备份与恢复流程

### 3.1 创建备份

1. 设置页先展示“备份包含个人财务数据，请保存到可信位置”；
2. 用户确认后使用 `ACTION_CREATE_DOCUMENT` 选择位置；取消选择视为正常结束，不显示错误；
3. 在短 Room 事务中取得一致性逻辑快照，事务结束后再编码、计算摘要和压缩；
4. 输出成功后显示文件名、时间、大小和实体计数，应用不保存外部 URI。

### 3.2 恢复

1. 使用 `ACTION_OPEN_DOCUMENT` 选择文件，只取得本次读取授权；
2. 将输入流写入内部临时文件并执行完整结构、摘要与语义校验；
3. 页面展示备份时间、版本和实体计数；用户明确确认后继续；
4. 在 `noBackupFilesDir/pre-restore.pbk` 覆盖保存最新自动回滚快照；
5. 单个 Room 事务按“流水、预算、偏好、分类、账户、账本”的顺序清空，再按外键正序插入；
6. 任一步失败由 Room 回滚，原数据库保持不变。成功后重新初始化状态并删除暂存恢复文件，回滚快照保留。

备份和恢复由进程级数据变更互斥器串行化。恢复确认期间界面禁止其他写操作；应用没有后台写入或同步任务。

## 4. CSV 导出

CSV 与完整备份使用独立入口和文案。用户选择含首尾日期的闭区间，查询转换为本地日期的左闭右开 epoch-day 范围，结果按发生时间升序。

固定列顺序为：

```text
type,amount,currency,category,account,target_account,occurred_at,note,created_at,updated_at
```

文件编码为 UTF-8，首部写 BOM，行尾固定 CRLF。所有文本按 RFC 4180 规则转义：包含逗号、双引号、CR 或 LF 时加双引号，内部双引号写成两个双引号。金额输出正数、两位小数；时间输出带偏移量 ISO-8601；不导出内部 ID。取消系统文件选择不显示错误。

## 5. 金额隐私

`app_preferences.hide_amounts` 是金额遮罩的单一事实来源。根组合读取该 Flow 并向所有只读金额组件提供隐私状态：

- 开启后，首页、流水、统计、预算、账户和详情中的金额统一显示 `••••`；
- 图表可访问性描述不包含真实金额；
- 录入/编辑金额字段仅在用户明确进入编辑流程后使用真实值，避免遮罩导致误写；
- 备份包含该偏好，恢复后立即生效。

## 6. 可选应用锁

锁配置通过 Preferences DataStore 保存 `enabled` 和固定 30 秒后台超时，不进入 `.pbk`，也不保存系统认证结果、PIN 或生物特征。

- `MainActivity` 使用 `FragmentActivity` 承载 AndroidX Biometric；
- 显式固定 Fragment 1.8.9，避免 Biometric 1.1.0 的旧传递版本与 Compose Activity Result/SAF 请求码冲突；
- 启用前调用 `BiometricManager.canAuthenticate`。API 30+ 请求强生物特征或设备凭据；API 28/29 使用库支持的设备凭据回退；
- 冷启动且锁已启用时直接进入不含业务内容的锁定组合；真实业务导航树不在其后方组合；
- 退到后台时记录 `SystemClock.elapsedRealtime()`，回到前台达到 30 秒即锁定；墙钟变化不影响判断；
- 认证失败或取消继续停留在锁定页，成功后才组合业务内容；
- 启用应用锁期间设置 `FLAG_SECURE`，关闭后清除；设备无可用认证能力时拒绝启用并给出本地提示。

## 7. 分层与错误模型

- `backup/`：严格 DTO、验证器、ZIP 编解码、Room 快照映射和恢复协调；
- `export/`：日期查询、CSV 编码和 SAF 输出；
- `security/`：DataStore 设置、单调时钟锁策略和系统认证桥接；
- UI/ViewModel 只接收阶段状态与有限错误，不读取 DAO、不记录 URI 或文件内容。

错误归一为：文件格式不支持、版本过新、文件损坏、数据不一致、文件过大、空间不足、认证不可用和未知本地错误。错误消息不得包含用户 URI、账户名、备注或财务值。

## 8. 数据库与版本

I4 只增加 DAO 查询/事务方法和外部格式 DTO，不新增表、列、索引或触发器。Room `version=1`、导出 schema 和 identity hash 必须保持不变。应用锁配置使用独立 DataStore，避免把设备安全状态混入可携带财务备份。

## 9. 验证重点

- 黄金样本往返后逻辑实体一致，摘要和清单计数一致；
- 损坏摘要、未知字段、未来版本、重复/穿越 ZIP 条目、超限和悬空引用均在数据库变更前拒绝；
- 注入恢复事务故障后原数据及关键聚合不变，回滚快照可读；
- CSV BOM、CRLF、固定列、顺序、日期边界和特殊字符完全确定；
- 金额遮罩覆盖视觉文本和可访问性语义；锁定组合不包含真实业务内容；
- API 28/36 系统认证分支、后台超时、认证失败/取消和成功路径；
- 无网络权限、无存储权限、关闭系统自动备份、schema v1 不变。
