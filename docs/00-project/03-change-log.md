# 变更记录

## CR-001：调整 Android 平台下限与设备矩阵

| 项目 | 内容 |
|---|---|
| 提出日期 | 2026-07-21 |
| 提出人 | 用户 |
| 状态 | 已撤销（CR-002） |
| 关联决策 | DEC-006、DEC-014、DEC-015 |

### 变更内容

- `minSdk` 从 Android 9（API 28）调整为 Android 8.0（API 26）。
- 删除 API 37 模拟器及 Android 17 前向兼容测试项。
- `compileSdk` 与 `targetSdk` 继续保持 API 36。

### 影响分析

- 需求：更新 NFR-030、Q-001 和需求基线中的兼容性下限。
- 技术：API 26 已提供 `java.time`；应用锁统一通过 AndroidX Biometric，并为 API 26/27 保留能力检测和兼容分支。
- 测试：最低版本模拟器改为 API 26，并增加 API 27 认证兼容检查；不再准备 API 37 系统镜像。
- UX、数据模型、备份格式与 MVP 功能范围不受影响。

### 验收结果

- 所有需求与技术设计文档不再把 API 28 表述为最低支持版本。
- 设备矩阵不再包含 API 37 / Android 17。
- 技术追踪矩阵、风险清单和 ADR 已同步。

## CR-002：恢复原 Android 平台方案

| 项目 | 内容 |
|---|---|
| 提出日期 | 2026-07-21 |
| 提出人 | 用户 |
| 状态 | 已接受并完成文档同步 |
| 关联决策 | DEC-016 |

### 变更内容

- 撤销 CR-001，`minSdk` 从 API 26 恢复为 Android 9（API 28）。
- 恢复 API 37 模拟器，用于 Android 17 前向兼容测试，不作为发布目标。
- `compileSdk` 与 `targetSdk` 继续保持 API 36。

### 影响分析

- 删除 API 26/27 专项兼容分支和设备矩阵要求。
- 应用锁最低测试边界恢复为 API 28，并保留 API 28/29 的认证器组合测试。
- UX、数据模型、备份格式与 MVP 功能范围不受影响。

### 当前生效基线

- 最低支持：Android 9（API 28）。
- 构建与目标：`compileSdk=36`、`targetSdk=36`。
- 模拟器：API 28、API 36、API 37；其中 API 37 只做前向兼容测试。

## CR-003：API 37 本机测试调整为可选

| 项目 | 内容 |
|---|---|
| 提出日期 | 2026-07-22 |
| 提出人 | 用户 |
| 状态 | 已接受并完成文档同步 |
| 关联决策 | DEC-018 |

### 变更内容

- 保留已下载的 API 37 16 KB 系统镜像和 `PBK_API_37` AVD 配置。
- 因当前机器内存不足，API 37 启动与前向兼容验证改为可选、可延期。
- API 37 不作为环境验收、工程初始化或发布门槛。

### 不变项

- `minSdk=28`、`compileSdk=36`、`targetSdk=36` 不变。
- API 28 最低版本测试、API 36 日常/目标版本测试和目标真机验证仍为强制项。
- 将来资源允许或具备其他测试环境时，可补做 API 37 验证，无需修改应用构建目标。
